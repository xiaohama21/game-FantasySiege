# 结算战报与后续整备

> v0.1 · 2026-11-20 · GDD v0.5.7 / 程序0.1.3.0
> v0.1：完成战斗后显示实际贡献与脉冲作用，连接下一关、敌情和编队；不增加货币、存档或战斗数值收益。

结算同时显示奖励/保存状态和本场战报，使用分区纸页、属性图标和紧凑贡献表。玩家可了解实际有效对兵伤害、有效治疗、对基地伤害、召唤/阵亡，以及脉冲次数、命中与打断。统计是本次实际战斗的记录，不预测阵容必胜，也不将高伤害等同于守线、治疗或控制价值。

SiegeBattle.get_battle_report()返回深拷贝：stage_id、outcome、elapsed、roster、levels、study_modifiers、members、totals、fixture。members按开局编队排序，含id/name/level/summons/fallen/damage/healing/base_damage/damage_taken；totals含summons/fallen/damage/healing/base_damage/damage_taken/energy_spent/pulse_uses/pulse_damage/pulse_targets/pulse_interrupts。数值均为累计量，初始为零。开局等级与研修取原战斗深拷贝；没有新存档schema，不写profile/preferences，不保留跨局战报历史。

对兵伤害按目标生命实际减少量记录，排除过量击杀；治疗按实际恢复量排除溢出；攻城按基地生命实际减少量记录。三者以战斗原有计算/生命改变为依据，不重写UnitStats、护甲、命中或技能公式，不改变原combat_event与_damage_unit返回语义。玩家总对兵伤害包含英魂与脉冲，成员伤害只归真实攻击者；脉冲另列，不归到最近英魂。只记录成功召唤/成功脉冲的能量支出；拒绝动作不记次数或扣费。阵亡每实例只计一次，退场清理不算死亡。

脉冲命中数为使用时实际被选中的敌军；打断数只计仍有待结算攻击被取消的不同攻击者，不把所有眩晕目标当成打断成功。死亡后取消攻击、暂停、倍速和战斗结束均保留原语义。性能夹具seed_performance_units显式标fixture=true，不能用其结果冒充自然玩家战报。

多次脉冲可反复命中同一敌军，所以界面命中标“人次”、打断标“次”，不宣称整场唯一人数。结算常显“对兵总伤害含脉冲；英魂表只计各自贡献”。治疗规则在图鉴/英魂/研修说明中保留“不能修复基地”，与实际治疗只选择己方单位的规则一致。

记录采用固定编队规模的小字典和事件时累计；不增加每帧全体遍历、每击新节点、日志或写盘。结束前冻结战报，再发送battle_finished；结束后读报、尸体清理、切结算分区均不改变统计。stop清理本局，下一次start重新归零。空阵容失败显示未召唤和零贡献，不能给出伪造成员。

Main结算只在原胜利信号或明确重试时调用领奖事务。报表渲染、切页、读报不调用win或发资源；已保存奖励用本次award快照显示，不从后续全局last_award猜测。本场时长采用逻辑elapsed，暂停不增加，2倍速仍按原逻辑时间。报告值为浮点累计，界面按现有整数显示规则取整，保留中文对兵/治疗/攻城含义。

正常保存成功后，可继续远征/再战、查看本关敌情、调整编队或回营地；导航经既有start_stage/show_home/_stop_battle。胜利保存失败突出重试，离开/下一关动作禁止静默丢失奖励，保留原退出确认。成功重试继续展示同一战报及保存后的奖励，再由玩家选择下一步。失败结算不发收益，返回整备不写入角色成长。

后台验收覆盖真实命中与护甲、范围多目标、过量伤害/治疗、攻城倍率和基地生命夹紧、玩家/敌军隔离、脉冲和待击打断、成功/失败召唤、死亡一次、暂停/倍速、结束冻结/新局归零和深拷贝。UI以实际Main结算验证有效值可见、重复渲染不重复领奖、奖励失败/重试、未来档保护、下一关与敌情/编队导航；原八关独立旅程复验。离屏画面增加胜利、失败、未保存及重试后结算。前台性能仍由用户延期，新增统计不能被后台通过标成已完成性能验收。
