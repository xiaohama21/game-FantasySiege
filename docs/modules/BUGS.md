# Bug 修复记录

> v0.2 · 2026-11-18 · GDD v0.2.0 / 程序0.1.1.0
> v0.2：记录接续初版时发现的存档恢复与未来版本保护边界。

新项目初始记录。每个后续修复填写：问题、复现、根因、处理、GDD版本与程序版本。实现前设计迭代不是运行时bug；真正发现的运行/导入问题均在此登记。

## FS-001：损坏主档恢复后再次保存会覆盖好备份

- 问题：主档损坏且备份有效时加载正常，但下一次保存先把损坏主档复制成备份，破坏恢复保障。
- 复现：建立有效档和备份，向主档写入无效JSON，重新加载后训练角色；查看备份会变成损坏内容。
- 根因：备份逻辑只检查文件存在，不检查内容有效。
- 处理：仅以有效主档更新备份；损坏主档保持原有有效备份。读档严格验证数组/整数/已知角色；未来schema通过原始头部阻止覆写。
- 验证：ProfileSmoke隔离路径覆盖损坏主档恢复并再次写入、未来schema不覆写、失败事务不扣费及重复奖励。
- 关联版本：GDD v0.2.0、CORE v0.4、程序0.1.1.0。

## FS-002：084骨架twoColor动画不能被4.3运行库加载

- 问题/复现：导入084底模，运行SpineProbe，Attack_A的槽颜色timeline加载失败。
- 根因：Spine3.8的twoColor七通道结构与4.3的rgba2字段/曲线表示不同，原转换器未适配。
- 处理：保留light/dark并适配rgba2七通道曲线；吕布/浮灵的deform同时按4.3结构转换并保留数据。
- 验证：13底模分进程运行，所有非空动画真实加载推进；视觉与性能独立验收。
- 关联版本：GDD v0.2.0、SPINE_PIPELINE当前版、程序0.1.1.0。

## FS-003：召唤卡与长规则文字超出固定区域

- 问题/复现：1280×720进入战场，八张卡的多行文字使Button最小宽度扩大并重叠；英魂详情的长规则文字越过纸页右边缘。
- 根因：Godot控件根据文本最小宽度扩张，原代码先设置尺寸再开启换行。
- 处理：Label/Button先启用clip_text避免自然宽度撑开；召唤卡用独立姓名/职责/费用/状态标签，维持明确的八个点击区。
- 验证：MainFlow重新生成属性页及战斗截图，检查边界和禁用状态可读性。
- 关联版本：GDD v0.2.0、UI_ART v0.1、程序0.1.1.0。

## FS-004：部分default皮肤没有角色身体

- 问题/复现：084/018/253/254使用default皮肤，加载成功但截图只见特效或空角色。
- 根因：源default皮肤是特效/共用槽集合，完整身体在A皮肤；只检测运行成功不足以证明可见。
- 处理：为对应配方选择A并重置setup槽，探针对非空原始动作检查有限正可见边界；朝向与实际轮廓另截图抽检。
- 验证：13底模全部非空动作原生探针与多动作双朝向截图。
- 关联版本：GDD v0.2.0、SPINE_PIPELINE当前版、程序0.1.1.0。

## FS-005：暂停/倍速未同步Spine视觉时钟

- 问题/复现：暂停后战斗逻辑停止，但独立SpineActor的_process仍继续动作；2×逻辑与1×动画不同步。
- 根因：战斗固定步与骨架自动播放分离，却没有显式同步视觉倍率。
- 处理：SiegeBattle.set_visual_playback统一同步所有实例，新增实例继承倍率；UI暂停和终局设0，恢复和倍速设1/2。
- 验证：BattleSmoke及MainFlow检查暂停不推进逻辑，新旧视觉倍率一致。
- 关联版本：GDD v0.2.0、CORE当前版、程序0.1.1.0。

## FS-006：64单位逻辑扫描耗尽帧预算

- 问题/复现：render_visuals=false，双方各32铁卫/黑曜卫推进5秒，耗时约5.35秒，每固定步17.83ms。
- 根因：每个实例全表索敌/友军阻挡及命中uid线性查找导致二次扫描成本。
- 处理：稳定有序的双方阵线、相邻友军缓存及uid字典，保留固定步、波次顺序和原判定。
- 验证：完整59项回归和三关结论不变；同负载5秒模拟耗约0.580秒，每步1.93ms。
- 关联版本：GDD v0.2.0、CORE v0.6、程序0.1.1.0。

## FS-007：未导入atlas纹理可能触发原生崩溃

- 问题/复现：新097使用原包不同PNG名称，直接构造骨架时纹理尚未经过Godot导入，原生atlas加载崩溃。
- 根因：Spine原生库把未能作为Texture2D加载的页面传入后续原生流程。
- 处理：SpineActor在创建骨架前确认atlas每个页面存在且可作为Texture2D加载，失败使用明确占位；bootstrap先执行编辑器导入，再进行独立探针。
- 验证：纯D69重导入后13套135原始动作、每动作36步均有有限正边界；缺少纹理不进入原生加载。
- 关联版本：GDD v0.2.1、SPINE_PIPELINE v0.3、程序0.1.1.0。

## FS-008：视觉倍率调用不存在的原生方法

- 问题/复现：实例入场调用set_playback_speed时，SpineAnimationState.get_current不存在，Godot记录SCRIPT ERROR，但进程返回0且内部UI断言未识别。
- 根因：按其他Spine运行库接口推测get_current，未对当前原生接口实测；单看退出码不足以判脚本运行成功。
- 处理：使用set_animation实际返回的TrackEntry持有引用并设置倍率；新增run_checks.py同时检查结束标记、返回码和SCRIPT ERROR/ERROR日志。
- 验证：真正Spine的召唤、暂停0、恢复1及2×经过MainFlow，严格runner必须无脚本错误。
- 关联版本：GDD v0.2.1、CORE v0.6、SPINE_PIPELINE当前版、程序0.1.1.0。
